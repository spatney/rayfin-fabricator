Use this page when the chat panel shows an error, a turn does not finish, or Copilot seems to lose context.

## Chat shows a Copilot error

You see an error bubble in chat, **Copilot needs your attention**, or a message such as "GitHub Copilot is not signed in. Sign in to Copilot in Fabricator, then retry your message.", "Session not found", "Execution failed: Error: Session was not created with authentication info or custom provider", "rate limit exceeded", or a model access error.

Fabricator sends your prompt to the bundled GitHub Copilot engine. Authentication, model access, policy, rate-limit, and session errors come from that engine.

1. If the error asks you to sign in, select **Sign in to Copilot** in chat and complete the browser or device-code flow.
2. Retry the message yourself. Fabricator keeps your displayed conversation and draft, but does not automatically replay work after a failed or partially started turn.
3. If the model pill shows a warning sign, or the model list says "Not available anymore. Choose another model.", open the model picker and turn on **Auto** or choose another model.
4. If models do not load, sign out and back in to Copilot from setup or the chat notice.
5. If the error mentions rate limits or unavailable service, wait a few minutes, choose **Auto** or a fast model, and retry.
6. If repeated "Session not found" errors continue on the latest version, start **New chat**. This clears the conversation view, not your app files.

If the same error repeats, [Report a problem](/docs/troubleshooting/report-a-problem).

## A chat turn seems stuck

The assistant appears to keep working, the work log stops changing, or you cannot tell whether a turn is still active.

Long turns can run for many minutes. Fabricator streams the work log, command output, file edits, and the final "Worked for …" summary when the engine reports the turn is idle.

1. Expand the work log and check the latest step or command output.
2. If you know what should happen next, type a short steering message while the turn is running. Fabricator queues it for the active session.
3. If the turn is clearly wrong or waiting forever, select **Stop**.
4. After stopping, send a smaller follow-up prompt that names the file or problem to continue from the current project state.
5. If the preview or deploy is also running, wait for it to finish before starting another large request.
6. If Fabricator stops responding, restart it. Your project files and saved chat history are stored on disk.

If stuck turns happen repeatedly, turn on **Settings → Diagnostics → Full diagnostics**, reproduce once, then [Report a problem](/docs/troubleshooting/report-a-problem).

## The conversation disappeared or a new session started

You see an explanation that Fabricator started a new Copilot session, or chat history looks different after sign-in, restart, or **New chat**.

Fabricator keeps displayed chat history separately from the Copilot engine session. When the saved engine session is unavailable, Fabricator creates a new one so you can continue. **New chat** intentionally clears the visible conversation after confirmation and does not change your app files.

1. Update to the latest Fabricator version if this followed a "Session not found" error.
2. Continue in the visible chat if the history is still shown. Copilot can read the project files even if the engine session changed.
3. If history was cleared by **New chat**, describe the current task again or refer to the files that already changed.
4. Use the Code and History views to inspect or restore app file changes.

If history disappears without using **New chat**, [Report a problem](/docs/troubleshooting/report-a-problem).

## Copilot credits run out quickly

Your GitHub Copilot plan shows included credits or premium requests being used faster than expected during Fabricator work.

Fabricator uses your own GitHub Copilot entitlement. Each chat turn, deep review, design option, model selection, image attachment, and retry can use Copilot capacity. Fabricator cannot increase your plan limits.

1. Open the model picker and turn on **Auto**, or choose a model marked **Fast**, when you do not need a deep implementation pass.
2. Choose a lower **Effort** for small edits.
3. Break broad requests into smaller prompts with clear acceptance criteria.
4. Avoid repeated **Try again** or **Retry** on the same large prompt; steer with a shorter correction instead.
5. Use quick checks and local inspection before running deep Copilot reviews.
6. Attach screenshots only when visual context is necessary.

If usage looks unrelated to your prompts, collect diagnostics and [Report a problem](/docs/troubleshooting/report-a-problem). Diagnostics do not include your Copilot billing data.

## A model on your own API key shows an error

A chat turn, Advisor review or Design request on a model on your own API key stops with a message from the provider.

The provider runs these models and bills your account, so its key, credit and plan limits apply. Fabricator puts the provider's error in plain words:

| Message | What to do |
| --- | --- |
| "`<Provider>` didn't accept your API key. Replace it in Accounts, or choose another model." | In **Accounts → Model providers**, select **Replace** and paste a working key. |
| "Your `<Provider>` account is out of credit or over its spending limit. Check your billing with `<Provider>`, or choose another model." | Add credit or raise the spending limit on the provider's website. |
| "This request is bigger than your `<Provider>` plan allows per minute. Fabricator's requests are large, so upgrade your `<Provider>` plan, or choose another model." | Upgrade your plan with the provider, or choose another model. |
| "`<Provider>` is limiting how often your key can be used. Wait a minute and try again, or choose another model." | Wait a minute, then select **Retry**. |
| "`<Provider>` is overloaded right now. Try again in a minute, or choose another model." | Wait a minute, then select **Retry**. |
| "`<Provider>` doesn't offer `<model>` to your key anymore. Check your models in Accounts, or choose another model." | In **Accounts → Model providers**, select **Check again** to update the provider's list of models, and choose another model. |

1. Follow the step for your message in the table.
2. To keep working meanwhile, open the model picker and choose a Copilot model or **Auto**.

When you add a key, Fabricator checks it first. If the provider turns it down, you see "`<Provider>` didn't accept this key. Check that you copied all of it." and nothing is saved.

If an error keeps coming back with a working key, [Report a problem](/docs/troubleshooting/report-a-problem).

## A model on your own API key isn't available

A turn on one of your own models stops before it starts, with one of these messages:

- "`<model>` isn't one of your `<Provider>` models anymore. Turn it on in Accounts, or choose another model."
- "Your `<Provider>` API key isn't set up. Add it in Accounts, or choose another model."
- "`<model>` isn't available anymore. Choose another model."

The chat, Advisor or Design bar is set to a model that the pickers no longer offer: you turned the model off or removed its key. Fabricator never switches to another model by itself.

1. Open the model picker. Its pill shows a warning sign next to the model.
2. Choose another model, or turn on **Auto**.
3. To use the model again, turn it back on in **Accounts → Model providers**, or add its key again.

See [Use your own API keys](/docs/build/your-own-api-keys).

## The model stopped before finishing

A turn on one of your own models shows "The model stopped before finishing. Asking it to continue…", and sometimes ends with "The model stopped before finishing. Select Retry, or choose another model."

A model can end a response with no reply and no next step. Fabricator asks it to continue, up to twice, before it gives up.

1. Select **Retry**.
2. If it happens again, choose another model and send the request again.

If it keeps happening with one model, [Report a problem](/docs/troubleshooting/report-a-problem) and name the model.

## Rayfin CLI reports missing dependencies

Fabric sign-in, a deploy, the preview, or a workspace list fails with a Node error such as "Cannot find package" or "Cannot find module" that names a package like `rxjs`, `commander`, or `jsonwebtoken`.

The project's `node_modules` folder is incomplete. A package install that stops part way, for example when creating a project times out, leaves package folders empty, and a sync or antivirus tool can remove files from the folder.

Fabricator checks for missing or incomplete packages when you open a project and before it deploys or signs in to Fabric, and reinstalls them. When a Rayfin CLI command fails because a package is missing a file, the log says "Some of this project's packages didn't install completely", and Fabricator reinstalls that package at its next check.

1. Deploy again from the app bar, where the button says **Try again** after a failed deploy, or select **Sign in to Fabric** again. Fabricator reinstalls the incomplete packages first.
2. If the error comes back, close Fabricator and delete the project's `node_modules` folder. Then open Fabricator and the project again, and Fabricator installs all of the project's packages.

If the error keeps coming back, [Report a problem](/docs/troubleshooting/report-a-problem) and include the exact error.
