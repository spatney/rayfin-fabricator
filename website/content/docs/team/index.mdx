> [!WARNING]
> Team workspaces are an experiment. Turn them on in **Settings → Experiments**. They may change or be removed in a future update.

Team workspaces let several people build Rayfin apps together without sharing one laptop or one deployment. Fabricator keeps the team's apps in GitHub, gives each person a working copy that runs on their own computer, and publishes the shared app through a GitHub Actions pipeline.

![Home with the Team workspaces experiment turned on, showing a Build apps together card with Create a team workspace and Join one.](/screenshots/team-home.webp)

## How a team workspace works

A team workspace is one private GitHub repository. Each top-level folder that contains `rayfin/rayfin.yml` is one Rayfin app.

While you work on a team app, it runs on your computer like any app you build, with its own local data. See [Develop on this computer](/docs/build/local-development). After each chat turn, Fabricator saves your changes to your own working branch on GitHub, in a draft pull request, so your teammates can see what you're working on. A draft pull request deploys nothing.

Fabricator also creates two Microsoft Fabric workspaces:

- one workspace for published apps that everyone uses
- one workspace for everyone's personal previews

When you publish, Fabricator marks your pull request ready for review, and the pipeline deploys your personal preview as a check. Then Fabricator merges your changes, and the pipeline deploys the published app.

The repository pipeline signs in to Microsoft Fabric with Microsoft Entra ID service principals called deploy identities. It uses GitHub OIDC, so Fabricator stores IDs as GitHub Actions variables but stores no client secrets.

Pull requests can only use the preview identity. Pushes to `main` use the deploy identity for published apps. That means a pipeline change in a pull request cannot touch the published apps workspace.

```mermaid
flowchart LR
  You["You"] --> Local["Your app on this computer"]
  Local --> Branch["Your working branch"]
  Branch --> PullRequest["Draft pull request into main"]
  PullRequest --> Publish["Publish marks it ready, then merges it"]
  Publish --> PreviewWorkflow["Preview workflow"]
  PreviewWorkflow --> PreviewWorkspace["Previews Fabric workspace"]
  Publish --> Main["main branch"]
  Main --> PublishWorkflow["Published workflow"]
  PublishWorkflow --> PublishedWorkspace["Published apps Fabric workspace"]

  class You actor
  class Branch,PullRequest,Main store
  class Local,PreviewWorkflow,Publish,PublishWorkflow service
  class PreviewWorkspace,PublishedWorkspace external
```

## Turn on the experiment

1. Open **Settings**.
2. Open **Experiments**.
3. Turn on **Team workspaces**.
4. Make sure the GitHub CLI `gh` is installed. Fabricator uses it for team repositories.

![The Experiments section of Settings, with its note that experiments are off by default and may change, and the Team workspaces, Migrate Power BI reports, Work IQ and Parallel UI builder switches, all off.](/screenshots/settings-experiments.webp)

Turning the experiment off hides team workspaces and team apps in Fabricator. It does not delete the GitHub repository, Fabric workspaces, apps, deploy identities, or local files.
