Fabricator signs in to a few services for you. **Accounts** shows who you're signed in as for each one, and which organization (Microsoft Entra ID tenant) the account belongs to. From there you can sign in, add more accounts, choose the one to use, and sign out without leaving your project.

{/* screenshot: accounts */}

## Open Accounts

Open **Accounts** in any of these ways:

- In the app bar, select your account avatar, then select **Manage accounts…**. When you're not signed in to Microsoft Fabric, select the arrow next to **Sign in to Fabric**, then select **Manage accounts…**.
- Open **Settings** and select **Manage accounts**.
- When a bar under the app bar says you're not signed in to an account, select **Manage accounts** in that bar.

Changes apply to every project on this computer. Select **Re-check** to verify every account again, and **Done** to close **Accounts**.

## What each account is for

| Account | What Fabricator uses it for | Several accounts |
| --- | --- | --- |
| **GitHub Copilot** | Writes and edits your app's code when you chat. | One at a time |
| **Microsoft Fabric** | Deploys, hosts and shares your apps, lists your Fabric workspaces, and manages secrets. | Yes |
| **Azure CLI** | Finds people when you share an app, connects Fabric data, and sets up team workspaces. | Yes |
| **GitHub** | Clones repositories and runs team workspaces. It's optional and uses the GitHub CLI. | Yes |

**Accounts** also has **Model providers**, where you add API keys for Anthropic, OpenAI, xAI and Google. See [Use your own API keys](/docs/build/your-own-api-keys).

A check mark next to a service's name means you're signed in. Otherwise the service says **Not signed in**, **Checking…** or **Needs attention**. **Needs attention** means Fabricator couldn't verify the sign-in; the message in that service's card says why.

If Fabric and the Azure CLI are signed in to different organizations, **Accounts** warns you: sharing an app and connecting data look people up through the Azure CLI, so use one organization for both. The warning offers the fix. If the Azure CLI already has an account in Fabric's organization, select `Use <account> in the Azure CLI`. Otherwise select `Sign in to <organization> in the Azure CLI`, which opens **Add account** for the Azure CLI with Fabric's organization filled in.

## Use more than one Fabric account

You can stay signed in to several Fabric accounts, for example your work account and an account in a client's organization. Fabricator uses one of them at a time, marked **In use**. Deploying, listing workspaces, sharing and secrets all use that account.

To add a Fabric account:

1. In **Microsoft Fabric**, select **Add account**.
2. Optionally, in **Organization (optional)**, enter the organization to sign in to, as a domain such as `contoso.onmicrosoft.com` or as a tenant ID. Use it for an organization you're a guest in. Leave it empty to use your account's own organization.
3. Select **Continue**, then finish signing in in the browser window that opens.

The account you added is in use as soon as you're signed in.

To switch accounts, select **Use** next to the account. To sign out of an account you aren't using, select **Sign out** next to it, then select **Sign out** again to confirm. To sign out of the account in use, select **Sign out** next to it. Fabricator then uses another signed-in Fabric account, if you have one.

The first Fabric account you sign in to is the Rayfin CLI's own sign-in, so `rayfin` in a terminal uses it too. Fabricator keeps the accounts you add after it to itself.

> [!NOTE]
> On macOS, the Rayfin CLI keeps every Fabric account's sign-in in one keychain item. Signing out of one Fabric account signs all of them out until you sign in again.

## See which account deploys

In the app bar, select the deployment control. Under **Account**, its panel names the account that deploys, for example "alice@contoso.com · Contoso". Select **Change** to open **Accounts**.

## Use more than one Azure CLI account

The Azure CLI can stay signed in to several accounts, for example the same person in two organizations. The account marked **In use** is the one the Azure CLI uses now.

- To add an account, under **Azure CLI**, select **Add account**. Optionally enter an organization, select **Continue**, and finish signing in in your browser. The account you added becomes the one in use.
- To switch accounts, select **Use** next to the account.
- To sign out of an account, select **Sign out** next to it. Your other Azure CLI accounts stay signed in.

The Azure CLI's accounts are shared with your terminal, so these changes apply there too.

## Use more than one GitHub account

**GitHub** lists every account the GitHub CLI is signed in to. The account marked **Default** is the one **Clone from GitHub** and your terminal use. Team workspaces remember their own account.

- To add an account, select **Add account** and finish signing in in the terminal window that opens. Your default account stays the same. Fabricator lists the new account when you're done; select **Stop waiting** if you change your mind.
- To use another account for cloning, select **Make default** next to it.
- To sign out of an account, select **Sign out** next to it, then select **Sign out** again to confirm. This also signs the account out of the GitHub CLI in your terminal.

If the GitHub CLI isn't installed, select **Install from setup**.

## Switch your GitHub Copilot account

Copilot uses one GitHub account at a time. To use a different one:

1. In **GitHub Copilot**, select **Sign out**.
2. For GitHub Enterprise Cloud with data residency, enter your enterprise host in **GitHub host**, such as `company.ghe.com`. Otherwise leave `github.com`.
3. Select **Sign in**.
4. On the GitHub page that opens, enter the code that **Accounts** shows. Select **Copy** to copy the code, or **Open GitHub** to open the page.

If sign-in doesn't work, see [Setup and sign-in problems](/docs/troubleshooting/setup-and-sign-in).
