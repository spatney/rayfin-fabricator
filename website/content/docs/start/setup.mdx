Setup prepares your computer for Fabricator the first time you open it. It has three steps: connect GitHub Copilot, install the tools, and sign in to Azure. The first two are required. Signing in to Azure is optional, and you can do it later. Work down the page, then choose **Enter Fabricator**. If the required steps are already done, Fabricator skips setup and opens straight to Home. After that, Fabricator opens on your work after a short welcome.

![The setup screen with all three steps complete: GitHub Copilot connected, the tools installed and the optional Azure sign-in done, above a You're all set block offering Enter Fabricator.](/screenshots/setup.webp)

## Step 1: Connect GitHub Copilot

GitHub Copilot is the AI agent that writes and edits your app. Fabricator uses its bundled Copilot engine, so nothing needs installing first — this is why it comes first.

Connecting Copilot also turns on **Help**, the assistant in the bar at the bottom of the screen. If anything in the next two steps goes wrong, Help reads what happened and explains it, so it's worth doing this before the rest.

For a standard GitHub account, leave **GitHub host** as `github.com`. For GitHub Enterprise Cloud with data residency, enter your Enterprise Cloud host, such as `company.ghe.com` or `https://company.ghe.com`. The field accepts `github.com` or a `.ghe.com` Enterprise Cloud host. GitHub Enterprise Server is not supported by this sign-in flow.

Choose **Sign in**, then finish the browser or device-code instructions shown by Fabricator.

## Step 2: Install the tools

Fabricator uses a few free tools behind the scenes, and can install them for you.

| Tool | Required | Minimum | What it is used for |
| --- | --- | --- | --- |
| Node.js | Yes | 22.12 | Runs your app on this computer while you build it. |
| npm | Yes | Any installed version | Fetches the building blocks your app is made from. |
| Git | Yes | Any installed version | Keeps a history of your app so you can always go back. |
| GitHub CLI (gh) | No | Any installed version | Lets Fabricator work with your code on GitHub. |

With the **Local development** experiment on, this step also lists **Local backend**: rayfin-local, which comes with Fabricator and runs your apps and their data on this computer, so there's nothing to install. Setup checks that it runs. It doesn't stop you entering Fabricator, but your apps can't run on this computer without it. If Windows blocks it, see [Windows blocked rayfin-local](/docs/troubleshooting/preview#windows-blocked-rayfin-local). For the experiment, see [Develop on this computer](/docs/build/local-development).

For missing tools, choose **Install** on one row, or **Install all** to install the missing required tools in one go. On Windows, Fabricator tries `winget`. On macOS, it tries Homebrew. If that is not available or an install cannot run automatically, Fabricator opens the tool's official installer and shows **Get it**.

Installing downloads from the internet. If you are offline, the install buttons are disabled and setup says so; reconnect and choose **Re-check**.

After a tool install, setup can show:

> "Almost there. Restart to finish setting up the tools that were just installed."

Choose **Restart now**, then return to setup. Use **Re-check** when you have installed or fixed a tool yourself.

### When an install fails

Setup explains what went wrong in plain language instead of showing the installer's raw message — for example that another installation is already running, that Fabricator doesn't have permission, or that it couldn't reach the internet — along with what to do about it.

Choose **Show details** to see the original message, or **Ask Help** to have the assistant look into it. Help is available once step 1 is done.

## Step 3: Sign in to Azure

This step is marked **Optional**, and doesn't stop you entering Fabricator. It says "Optional. Lets you share apps, add Fabric data and migrate Power BI reports. You can also sign in later." If you skip it, those features ask you to sign in when you use them, for example with a **Sign in to Azure** button. Team workspaces need an Azure sign-in too. With the **Local development** experiment on, apps that run on this computer also reach Azure and Fabric data with your Azure sign-in.

1. If the Azure CLI isn't installed, choose **Install** in this step. Where Fabricator can't install it for you, the step shows **Get it**, which opens the Azure CLI's install page.
2. Choose **Sign in**, then complete `az login` in the browser.

If the sign-in fails, setup says why, but you can still enter Fabricator.

## What each account is for

- GitHub Copilot writes code, edits files, answers chat prompts, and powers **Help**. It's the only account setup requires.
- The Azure CLI, when you sign in to it, finds people to share with, connects Fabric data, reads the Power BI reports you migrate, and sets up team workspaces. With the **Local development** experiment on, apps that run on this computer read Fabric data with it too.
- Fabric sign-in is separate. Fabricator asks you to **Sign in to Fabric** when it needs the project's Rayfin CLI to list workspaces, publish, share, or refresh Fabric credentials. A new app is published before you build it with chat, so that's usually in the **Publish your app** step of your first project.

You can see and change all of these later, including adding more Fabric and Azure CLI accounts. See [Manage your accounts](/docs/start/accounts).

## Sign out and re-check

When an account is signed in, its row offers **Sign out**. Copilot sign-out removes the current Copilot account from the bundled engine. Azure sign-out runs `az logout` for the account in use and verifies that it's gone. Any other accounts the Azure CLI is signed in to stay signed in, and one of them becomes the one in use.

After signing out, installing a tool, or changing account state, choose **Re-check**.

## Enter Fabricator

A step you have finished collapses to a single line with a check mark. Select **Details** on any of them to open it again. Step 3 stays open until you sign in to Azure.

When the required tools are installed and GitHub Copilot is connected, a **You're all set** block appears at the end of the page with **Enter Fabricator**. If you skipped Azure, it says "Your tools are installed and GitHub Copilot is connected. Sign in to Azure whenever you need it." Choose **Enter Fabricator** to open Home.

## Later launches

Once setup has passed, Fabricator skips setup. Each launch shows a short welcome screen while your work loads behind it: Ray swims in and welcomes you back, and the line under the Fabricator logo names the project that's opening. The welcome fades away once your project is ready, usually within a second or two, and you're back where you left off.

Meanwhile, Fabricator checks your tools and accounts in the background. Until the check finishes, the account control in the app bar shows a spinner instead of **Sign in to Fabric**.

If the check finds a problem, a bar under the app bar says what it is, for example "Not signed in to GitHub Copilot." Select **Manage accounts** to sign in, or **Review setup** to fix a missing tool. The bar doesn't stop you working; close it with its ✕ button. Azure and Fabric are optional, so the bar never mentions them.

To open setup yourself, open **Settings** and select **Open setup**. Until every check passes, setup offers **Back to Fabricator** to return without finishing.

If setup does not pass, see [Setup and sign-in troubleshooting](/docs/troubleshooting/setup-and-sign-in).
