Search finds anything in Fabricator from one box: your projects, the things you can do, the documentation, and the files in the open project. It also asks Help, and shows the answer right in the box.

![Search with "deploy" typed: one list of results led by the Deploy 3 changes action, then documentation pages and sections and the Turn off Deploy after each chat turn action, with Ask Help "deploy" below. The bar at the bottom shows Run action and Actions.](/screenshots/search.webp)

## Open Search

1. Press `Ctrl+K` (`Cmd+K` on macOS), or in the app bar, select **Search**.
2. Type what you're looking for.
3. Press the arrow keys to choose a result, and press `Enter` to open it.

The bar at the bottom of Search says what `Enter` does with the result you're on, such as **Run action** or **Open in browser**. To close Search, press `Esc` or select outside it.

Search opens on Home, in a project and in a workspace overview. It doesn't open over a dialog or Help, or while you create, clone or migrate a project.

> [!NOTE]
> When you're working in your app in the preview, the preview receives your keys. Select anywhere else in Fabricator, then press `Ctrl+K`.

If you come back within a minute and a half, Search opens where you left it, with your last search selected so you can type over it. After that, it starts over.

## What Search finds

| Results | What opening one does |
| --- | --- |
| Projects | Opens the project, as it would from Home. A project whose folder is missing opens its management dialog instead. |
| Team workspaces | Opens the workspace overview. They show when **Team workspaces** is turned on in **Settings → Experiments**. |
| Actions | Does what the matching control does: switch to **Build**, **Code**, **Blueprint** or **Advisor**, open **History**, **Skills** or **Secrets**, deploy, **Share**, change the theme or text size, open **Settings**, manage accounts or API keys, open setup, and more. |
| Documentation | Opens the page, or the section of it, in your browser. |
| Files | Opens the file in **Code**. Search lists the open project's files once its packages are ready, leaving out what git ignores. |

Search ranks everything in one list, best match first, and shows a few of each kind. The end of each row says what the result is: **Project**, **Workspace**, **Action**, **Docs** or **File**. Under the results, **Use “…” with…** offers to ask Help, or to search only projects, actions, the docs or files, with how many of each match.

You don't have to type whole words. The start of a word works, and so do the first letters of several: `np` finds **New project**. Search also remembers what you open, so the things you use most rise to the top.

## Before you type

With nothing typed, Search offers:

- **Suggestions** for what's going on, such as **Deploy 3 changes** when your app has changes it doesn't have yet, or **Review 2 Advisor issues**.
- **Recent projects**. A green dot marks the one that's open.
- **Search**: **Search projects**, **Search actions**, **Search the docs** and **Search files**.
- **Ask Help**: questions to ask. After a deploy fails, the first one is **Find out why the deploy failed**.

## Search one kind of thing

To search only projects, actions, the docs or files, select **Search projects**, **Search actions**, **Search the docs** or **Search files**, or press `Ctrl+1` to `Ctrl+4` (`Cmd+1` to `Cmd+4` on macOS). What you typed comes along. To go back to everything, press `Esc`, select the back arrow, or press `Backspace` in the empty box.

**Search files** is available once a project is open and its packages are ready.

## Do more with a result

Press `Ctrl+K` (`Cmd+K` on macOS) in Search, or select **Actions** at the bottom, to see everything the result you're on can do. Type to narrow the list, then press `Enter`. Press `Esc` to put it away.

| Result | Actions |
| --- | --- |
| Projects | **Open project**, **Open in VS Code**, **Copy path** and **Manage project** |
| Team workspaces | **Open overview** and **Copy repository** |
| Actions | **Run action** |
| Documentation | **Open in browser** and **Copy link** |
| Files | **Open in Code** and **Copy path** |
| Help's answer | **Open in Help**, **Copy answer**, **Stop answering** or **New conversation**, the steps Help suggests, and the pages it used |

**Open in VS Code** opens the project's folder in VS Code. If VS Code isn't installed, Fabricator opens the folder instead.

## Ask Help from Search

Ask Help the way you would in Help itself, without leaving what you're doing.

1. Type your question, such as "why did my last deploy fail?".
2. Press `Tab`. When what you typed reads as a question, **Ask Help** is also the first result, so `Enter` asks too. `Ctrl+Enter` (`Cmd+Enter` on macOS) asks Help whatever you typed.
3. Read the answer as it arrives. Help shows what it checked, the answer, and buttons for the steps it suggests. To scroll it, press `↑` and `↓`, or `Page Up` and `Page Down`.
4. To follow up, type your next question and press `Enter`.

To carry on in the full-screen Help, select **Open in Help** or press `Ctrl+J` (`Cmd+J` on macOS). It's the same conversation, so nothing is lost, even while an answer is still arriving. To stop an answer, press `Esc`. **Copy answer** and **New conversation** are under **Actions**.

Search and Help share one conversation. With nothing typed, **Continue your Help conversation** picks up where it left off. See [Ask Help](/docs/troubleshooting/help).

> [!NOTE]
> Help needs you to be signed in to GitHub Copilot. If you aren't, asking Help from Search opens the same dialog as Help does, which offers to sign you in, open the documentation, or start a bug report.

## Keyboard shortcuts

| Key | What it does |
| --- | --- |
| `Ctrl+K` | Open Search. In Search, show what the result can do |
| `↑` `↓` | Choose a result. Reading Help's answer, scroll it |
| `Enter` | Do what the bar at the bottom says. In Help, ask the question |
| `Tab` | Ask Help what you typed |
| `Ctrl+Enter` | Ask Help what you typed, from anywhere in Search |
| `Ctrl+1` to `Ctrl+5` | Search only projects, actions, the docs or files, or ask Help |
| `Ctrl+J` | Carry on in the full-screen Help |
| `Esc` | Put away actions, stop an answer, go back, clear the box, then close Search |

On macOS, press `Cmd` instead of `Ctrl`.
