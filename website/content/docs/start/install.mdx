Download Fabricator from the latest GitHub release, then launch it and complete setup.

## Windows

Fabricator ships a Windows NSIS installer. The installer mode is current-user, so it installs for your Windows account instead of requiring a machine-wide install.

1. Open the [latest Fabricator release](https://github.com/spatney/rayfin-fabricator/releases/latest).
2. Download `Rayfin Fabricator_<version>_x64-setup.exe`.
3. Run the installer.
4. If Windows SmartScreen appears, choose **More info → Run anyway**.
5. Launch **Rayfin Fabricator**.

The Windows release workflow signs the installer when the signing configuration is available. The expected publisher is Sachin Patney. SmartScreen can still warn for new or low-reputation downloads.

The installer also puts rayfin-local next to Fabricator in its install folder, `%LOCALAPPDATA%\Rayfin Fabricator` by default. rayfin-local is the local backend that runs your apps on this computer; see [Develop on this computer](/docs/build/local-development). The release workflow signs it with the same certificate as the installer, and there's nothing else to install for it. On a PC your organization manages, Windows can block it; see [Windows blocked rayfin-local](/docs/troubleshooting/preview#windows-blocked-rayfin-local).

## macOS

Fabricator's macOS build is for Apple Silicon.

1. Open the [latest Fabricator release](https://github.com/spatney/rayfin-fabricator/releases/latest).
2. Download `Rayfin Fabricator_<version>_aarch64.dmg`.
3. Open the DMG and drag **Rayfin Fabricator.app** to **Applications**.
4. If macOS says the app is damaged or cannot be opened, clear the download quarantine flag once:

   ```bash
   xattr -dr com.apple.quarantine "/Applications/Rayfin Fabricator.app"
   ```

The release workflow builds an Apple Silicon DMG. When Apple notarization is not configured, macOS can quarantine the downloaded app even though it is the expected release artifact. Removing the quarantine flag lets macOS open the app. rayfin-local, the local backend that runs your apps on this computer, is inside the app, so the same command clears its flag too.

## First launch

On first launch, Fabricator opens setup. Setup checks the tools on this computer and asks you to sign in to GitHub Copilot. Signing in to Azure is optional, and you can do it later. Continue with [Set up and sign in](/docs/start/setup).

## Updates

Fabricator checks GitHub Releases for signed updater artifacts when the app starts, every 4 hours while it's open, and as soon as your internet connection comes back after a check failed. If a newer signed release exists, Fabricator downloads it in the background. To check right away, restart Fabricator.

When the check at startup finds an update, Fabricator shows **Update available** with **Update now** and **Later**. If you choose **Later**, Fabricator opens normally and keeps the ready-update banner visible. An update found while you work goes straight to the banner.

While an update is downloading or ready to install, the banner can show a `Downloading update <version>…` status, an `Update <version> is ready to install` status, **Later**, and **Restart & update**. Installing an update stops the apps running on this computer, then restarts Fabricator. Selecting **Later** on the banner puts the update off until Fabricator starts again.

A required-update screen exists in the app, but the normal startup check is optional.

## Uninstall

Uninstall **Rayfin Fabricator** with your operating system's app removal flow:

- On Windows, use **Installed apps** or **Apps & features**.
- On macOS, remove **Rayfin Fabricator.app** from **Applications**.

Uninstalling the app does not necessarily remove projects, settings, logs, or CLI credentials. Your projects stay where they are. An app that ran on this computer keeps its local data in its project's `.rayfin-local` folder. See [Files and folders](/docs/reference/files) for leftover data locations.
