This quickstart takes you from an empty Fabricator install to a working Rayfin app that you can refine in chat. The app runs on this computer from the moment you create it, so you don't need a Fabric workspace to start.

## Create a project

1. On Home, select **New project**.
2. In **Project name**, enter a name for the app.
3. Select **Create project**.

New projects start from the Rayfin CLI's default Universal App template; there's no template picker in the normal flow. To start from a ready-made app instead, see [Start from a community example](/docs/build/projects#start-from-a-community-example).

{/* screenshot: new-project */}

Fabricator creates the project with the newest Rayfin release it can run on this computer, installs its packages, and starts its version history with git. Then it opens the project in the **Build** view, with chat ready for your first prompt. There's no deploy step: Fabricator starts the app and its backend on this computer, and the preview shows it as soon as it's running.

## Describe the app

When the Build view opens, type a prompt in chat. Start with the outcome, the people using the app, and the data they need to track.

```prompt title="Track equipment requests"
Build an equipment request app for an operations team. Employees request a laptop, monitor, phone, or accessory with a reason and needed-by date. Managers review requests, approve or reject them with a comment, and see a dashboard of open requests by type and priority.
```

For a smaller first pass, try:

```prompt title="Simple team tracker"
Build a simple team task tracker. Each task has a title, owner, due date, status, and notes. Show a board grouped by status and a summary of overdue tasks.
```

## Watch Copilot work

![A chat turn in progress: the work log lists the files Copilot edited and the command it is running, while the preview shows the app on localhost as it changes.](/screenshots/chat-working.webp)

While a turn runs, the chat shows a live work log with steps such as file reads, searches, commands, and edits. The preview shows the app as it changes: new screens appear as Copilot saves them, and changes to the app's data model and functions apply on this computer too.

When the turn finishes, Fabricator saves the chat history and checks the project's Rayfin version. Nothing is published: the changes stay on this computer until you publish them.

## Try the app

![The Fabricator workbench. On the left, the chat shows a finished Copilot turn that built an expense tracker; on the right, the preview shows the running app with a monthly total and a spending chart.](/screenshots/workbench.webp)

The right side of the **Build** view shows your app, running on this computer with its own backend. Its data, sign-in and functions run here too, so you can add records and try each page. The app signs you in by itself, and its data starts empty and stays on this computer.

To reload the app, open it in your browser, or change it visually, see [Preview your app](/docs/build/preview) and [Design mode](/docs/build/design).

## Iterate

Continue with another prompt. You can ask for a feature, attach a screenshot, mention files with `@`, or use **Design** to queue visual changes and send them to Copilot.

Good next prompts are specific:

```prompt title="Add reporting"
Add a reporting page that shows requests by status, requests by equipment type, and average approval time. Keep the dashboard readable on a laptop screen.
```

## Publish and share

When you want other people to use the app, publish it to a Fabric workspace: select **Publish** in the app bar and pick a workspace. Rayfin apps need a workspace on a Fabric **F-SKU** or Power BI Premium **P-SKU** capacity. Publishing doesn't copy the data on this computer: the published app keeps its own data in Fabric. See [Publish your app](/docs/ship/deploy).

After that, your changes still stay on this computer until you publish again. To have Fabricator publish them after each successful chat turn, open the publish control in the app bar and turn on **Publish after each chat turn**.

Once the app is published, use **Share** to share it with people in your organization. See [Share your app](/docs/ship/share).
