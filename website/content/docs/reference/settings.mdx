Open **Settings** to manage your accounts, change how Fabricator looks, where new projects are created, how diagnostics are captured, and which experiments are on.

Settings groups its options into **General**, **Appearance**, **Diagnostics**, **Experiments**, and **About**. Each option shows its name and what it does, with its control on the right.

![The Settings dialog: Accounts, API keys, Setup and Workspace folder under General, then Theme and Text size under Appearance, and the start of Diagnostics.](/screenshots/settings.webp)

## Accounts

**Accounts** lists the services Fabricator signs in to: GitHub Copilot, Microsoft Fabric, the Azure CLI, and GitHub. Select **Manage accounts** to see who you're signed in as, sign in or out, and add or switch between Fabric, Azure CLI and GitHub accounts. See [Manage your accounts](/docs/start/accounts).

## API keys

**API keys** adds models from Anthropic, OpenAI, xAI and Google, on your own API keys, to the model pickers in Build chat, the Advisor and Design. The provider bills you for them, and you still sign in to GitHub Copilot, which runs the conversation. Select **Manage API keys** to add your keys and choose their models in **Accounts → Model providers**. See [Use your own API keys](/docs/build/your-own-api-keys).

## Theme

**Theme** controls the app's color theme.

| Option | What it does |
| --- | --- |
| **System** | Follows your operating system light or dark setting. This is the default. |
| **Dark** | Uses Fabricator's dark theme. |
| **Light** | Uses Fabricator's light theme. |

## Text size

**Text size** scales the whole interface. The choices are 100%, 110%, 125%, and 150%. The default is 100%.

Use this when Fabricator is hard to read on a large or high-DPI monitor. The setting is saved as the UI scale and is clamped by the app between `80%` and `200%` when stored.

## Interface zoom in the status bar

The status bar has an **Interface zoom** menu with the same values as **Text size**. Changing it updates the same setting and also scales the design tools.

## Workspace folder

**Workspace folder** shows where Fabricator creates new projects. The default is a `RayfinProjects` folder in your home directory.

Select **Change…** to pick a different folder. This changes where new projects are created; it does not move existing project folders.

## Usage stats

**Usage stats** is an informational note under **Diagnostics**. In the app, it says:

> We send your sign-in domain and a hashed email so we can see how the product is used. Your email, code, and apps stay on this device.

Telemetry is only active when a build includes a telemetry connection string. See [Privacy and telemetry](/docs/reference/privacy).

## Setup

**Setup** reopens the setup screen, which checks the tools Fabricator needs and can install missing ones, such as the optional GitHub CLI. Select **Open setup**. Until every check passes, setup offers **Back to Fabricator**. See [Set up and sign in](/docs/start/setup).

## Diagnostics

Diagnostics are saved on this device under the logs folder. **Diagnostics** also holds **Usage stats**, and its **Logs** row has **Export diagnostics** and **Open logs folder**.

### Full diagnostics

**Full diagnostics** is off by default. When it is off, Fabricator records lightweight chat-turn metadata such as timing, model, mode, tool names, outcomes, errors, attachment count, files modified, and whether a publish ran.

When **Full diagnostics** is on, Fabricator also captures prompts, responses, and tool output for each chat turn. Text fields are truncated before they are saved. Turn this on only when you need a more detailed bug report.

### Export diagnostics

**Export diagnostics** creates a Markdown diagnostics bundle in the logs folder and opens that folder. The bundle includes environment details, recent chat-turn diagnostics, recent crash or hang log entries and, with the **Local development** experiment, the last lines of your apps' local backend output. You decide whether to attach it to a bug report.

### Open logs folder

**Open logs folder** opens the local logs folder without creating a new export.

## Experiments

**Experiments** is collapsed by default. It includes features that are off by default and may change or be removed.

### Team workspaces

**Team workspaces** lets you build apps with a team in a private GitHub repository. Everyone works on their own copy, and a pipeline publishes to Fabric with a deploy identity that Fabricator sets up. Team apps never deploy from this computer. This experiment needs the GitHub CLI.

> [!WARNING]
> Team workspaces are an experiment. Turn them on in **Settings → Experiments**. They may change or be removed in a future update.

### Migrate Power BI reports

**Migrate Power BI reports** adds **Migrate a Power BI report** to Home. It turns a Power BI report into a new app that reads the report's semantic model live, and Copilot rebuilds the report's pages, visuals and filters one page at a time. This experiment needs the Azure CLI. See [Migrate a Power BI report](/docs/build/migrate-power-bi).

> [!WARNING]
> Migrating Power BI reports is an experiment. Turn it on in **Settings → Experiments**. It may change or be removed in a future update.

### Local development

**Local development** says "Run your apps and their backend on this computer while you build, and publish to Microsoft Fabric when you choose." It's off by default.

| | Off (the default) | On |
| --- | --- | --- |
| A new app | Opens on **Publish your app**. Chat stays locked until the app is published. | Opens in the workbench with chat ready. There's no publish step. |
| Where the app runs while you build | Against its published copy in Fabric. While Copilot works, the preview shows the app's pages from this computer with the published app's backend. | On this computer, on rayfin-local, the local backend that comes with Fabricator, with its own data in the project's `.rayfin-local` folder. |
| The preview | Your published app. | Your app on this computer. Once it's published, **Local** and **Published** switch between the two, and **Preview as** chooses who the app signs in as. |
| **Publish after each chat turn** | On by default. | Off by default. |
| A new app's Rayfin version | Rayfin's latest release. | The newest release the local backend runs, with the app's Rayfin packages kept on that release line, such as `~1.36.0`. Rayfin updates stop at that line too. |
| Also | | Setup lists **Local backend**, Blueprint has a **Data** view of the local data, and **Secrets** has a **Local value** for each secret. |

Turning it on starts the open app on this computer. An app you created with it off that isn't published yet opens with chat ready while it's on. Turning it off stops every app running on this computer, and leaves their local data in their project folders. Team apps work the same either way. See [Develop on this computer](/docs/build/local-development).

> [!WARNING]
> Local development is an experiment. Turn it on in **Settings → Experiments**. It may change or be
> removed in a future update.

## Publish after each chat turn

**Publish after each chat turn** isn't in Settings: it's in the publish control's panel in the app bar, next to the published app's details. When it's on, a chat turn that changes your app publishes it as the turn finishes. When it's off, your changes wait until you publish them.

Your choice applies to every project on this computer. Until you choose, it follows **Local development**: on while the experiment is off, and off while it's on. With the experiment on, it publishes only an app you've already published yourself. When your choice differs from the default, the publish control says so after the published app's name, with "· Auto" or "· Manual". See [Publish to Microsoft Fabric](/docs/ship/deploy#publish-after-each-chat-turn).

## About

**About** is the last section in Settings. It shows the installed Fabricator version and the Tauri, WebView2, and Copilot CLI versions it runs with. When the Copilot CLI has updated itself past the version that came with Fabricator, both are shown, for example `1.0.98 (bundled 1.0.96)`.

Select **Copy** to copy the versions for a bug report, one per line:

```text
Fabricator <version>
Tauri <version>
WebView2 <version>
Copilot CLI <version>
```

The exact Tauri, WebView2, and Copilot CLI values depend on the build and your computer.

**Help** has **Documentation** and **Troubleshooting**, which open these docs in your browser.

You don't need to check for updates yourself. Fabricator checks when it starts, every 4 hours while it's open, and as soon as your connection comes back after a check failed. See [Updates](/docs/start/install#updates).
