---
title: "Keep Rayfin up to date"
description: "Know when a project's Rayfin CLI and SDK are out of date, and let Copilot upgrade them together while keeping the app building."
---

Each Rayfin app pins its own Rayfin CLI and SDK packages. Fabricator reads those installed package versions and, when a newer Rayfin release is available, offers the update in the status bar. For an app other than a team app, it offers updates only up to the newest release it runs on this computer, so your app keeps running here.

![The Rayfin version control in the status bar, opened to show that the Rayfin CLI and SDK can be updated from 1.35.1 to 1.36.2 with Update with Copilot.](/screenshots/rayfin-version.webp)

## Read the Rayfin status

When a newer Rayfin release is on npm, the status bar shows the project's version as `Rayfin v<version>`, followed by the latest version, such as `↑ 1.36.2`. For an app other than a team app, it counts only the releases Fabricator runs on this computer. When the project is up to date, the status bar shows nothing for Rayfin.

Open it to see separate rows for:

- **Rayfin CLI**
- **Rayfin SDK**

The version checker reads `@microsoft/rayfin-cli` as the CLI package. Other `@microsoft/rayfin-*` packages are treated as SDK packages.

## Update with Copilot

When an update is available:

1. Select the Rayfin version in the status bar.
2. Review the version rows.
3. Select **Update with Copilot**.

Fabricator sends a prepared upgrade request to the Build chat. Copilot is asked to:

- set exact Rayfin package versions in `package.json`,
- run `npm install`,
- keep Rayfin SDK packages in lockstep,
- pin Rayfin connector packages to the new CLI version when the app uses them,
- check the installed Rayfin docs for deprecations and known limitations,
- update app code so it still builds and runs,
- not run `rayfin up` or publish the app itself.

The update reaches your published app the way any chat change does: when the turn finishes, if **Publish after each chat turn** is on and the app is published, and otherwise the next time you publish. The popover says which: "They reach Fabric when Fabricator publishes the app after the turn." or "They reach Fabric the next time you publish." Team workspace apps are published by their pipeline instead.

## Updates stop at the release Fabricator runs locally

Fabricator runs your app on this computer with a local backend that runs one line of Rayfin releases, such as 1.36.x. So:

- **Update with Copilot** offers the newest release on that line, and asks Copilot to upgrade to "the newest version Fabricator runs on this computer". For a team app, which doesn't run on this computer, it offers the latest release.
- New projects, team apps included, pin every `@microsoft/rayfin-*` package to that line with a `~` range, such as `~1.36.0`, so a later `npm install` doesn't move them to a release Fabricator can't run yet.
- The Advisor flags **Rayfin packages aren't pinned to a release Fabricator runs locally** when a package is outside that line, or declared with a range that lets the next install leave it.

An app on another release can misbehave on this computer. Once it's published, its preview uses the published app's backend instead. See [What runs only on Fabric](/docs/build/local-development#what-runs-only-on-fabric).

## Why lockstep matters

Rayfin packages ship as a family. The Advisor rule catalog checks that the SDK packages are on one version because mixing `@microsoft/rayfin-core`, `-client`, `-data`, `-auth`, `-auth-provider-fabric`, `-lib`, `-functions`, `-storage`, `-embed-host`, and `-local-dev` versions is untested and can break at runtime.

The CLI and SDK version independently, but newer releases carry fixes and match the current docs. See the [Rayfin changelog](https://rayfin.ai/docs/reference/changelog).

## Minimum version for current Fabricator features

Team workspaces require Rayfin **1.36.2 or newer**. New projects, team apps included, start on the newest release Fabricator runs on this computer, pinned to that line.

Older existing projects keep their pinned dependencies until you update them.

If you move an app into a team workspace, update older apps first with **Update with Copilot**.

## If dependencies are missing

When you open a project, Fabricator checks that the project's Rayfin CLI and the rest of its packages are fully installed, and installs any that are missing or incomplete before enabling the project tools. The check usually takes a moment. If it takes longer, you see a `Preparing <project name>` status and "Checking the project's Rayfin CLI and installing missing dependencies..." It checks again before it publishes or signs in to Fabric.

If installation fails, Fabricator shows **Couldn't install project dependencies** with **Retry installation** and **Switch projects**.

When your app's packages, or its functions' packages, aren't installed, the preview says "Your app’s packages aren’t installed" and offers **Install dependencies**. See [When your app doesn't start](/docs/build/preview#when-your-app-doesnt-start).

## Manual upgrade prompt

Use this for a team app if you want to start the upgrade yourself from the chat instead of the status-bar button:

```prompt title="Upgrade Rayfin packages"
Upgrade this app to the latest Rayfin release. Keep all Rayfin SDK packages on the same exact version, update the Rayfin CLI package too, run npm install, then check the installed Rayfin docs for deprecations or known limitations and update the app so it still builds.
```

For other apps, use **Update with Copilot** instead: the latest release may be one Fabricator can't run on this computer yet.
